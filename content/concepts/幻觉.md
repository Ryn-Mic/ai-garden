# 幻觉

> [!abstract] 一句话定义
> 模型一本正经地输出错误内容。它不是 bug，而是 [[大语言模型]]「预测下一个 token」这个目标自带的属性：**模型只保证像真话，不保证是真话**。

## 为什么重要

幻觉决定了你能把模型用到什么场景。只要任务的错误成本高（引用、数据、法律、医疗），就必须**外部校验**，而不是寄希望于换更强的模型。

> [!tip] 一句话判断
> 「模型知道 X」通常只是「模型能流畅地说出很像 X 的话」。两者在关键场景必须区分。

## 核心原理

### 为什么必然发生

模型在训练里学到的是「什么续写最像人话」。当被问到不知道的事，最像人话的续写仍然是**自信的陈述**而不是「我不知道」——因为它没见过多少「承认不知道」的样本。

三个放大因素：

| 因素 | 机制 |
| --- | --- |
| 知识没见过 | 训练截止日期之后的事、私有数据 |
| [[Token]] 级切分 | 生僻词被切碎，表征质量差 |
| 采样随机性 | 见 [[采样]]——温度高会放大"编"的倾向 |

### 常见类型

- **事实性**：编造文献、人名、数据
- **忠实度**：总结/翻译时添油加醋，说了原文没有的内容
- **指令性**：声称调用了工具/读了文件，实际没有（[[Agent]] 场景最危险）

## 怎么压（不是根治）

按成本递增：

1. **提示约束**：允许说"不知道"、要求标注依据——见 [[提示工程]]
2. **接外部知识**：[[RAG]]，把「回忆」变成「照着念」
3. **校验器**：格式校验、引用核对、代码跑测试——把最后一步交给确定性程序
4. **降低随机性**：见 [[采样]]

> [!warning] 常见误区
> - 换更大的模型 ≠ 消除幻觉，只是频率下降
> - [[微调]] 治标不治本：改的是习惯，不是知识的可靠性
> - Agent 场景里「声称做了但没做」比编事实更隐蔽——日志里查，别靠模型自述
