# Token

> [!abstract] 一句话定义
> 模型处理文本的最小单位。模型眼里没有"字"和"词"，只有一串 token——**一切输入输出、一切计费、一切长度限制，都以 token 计**。

## 为什么重要

三个直接后果：

1. **成本按 token 算**。API 报价是"每百万 token 多少钱"，输入输出分开计。
2. **上下文窗口按 token 算**。见 [[大语言模型]]——装不下的内容模型根本"看不见"。
3. **模型的第一步就是把你的文本切成 token**。切分方式决定了模型对某些词天然吃亏（如生僻词、拼音混排）。

## 核心原理

```text
"我爱机器学习" → ["我", "爱", "机器", "学习"] → [8821, 4467, 2983, 7282] → 各自查表得到向量
```

模型内置一张**词表**（vocabulary，几万到十几万条），把常见文本片段映射成整数 ID。训练前先把语料全部切成 token，推理时同样先切再处理。

### 经验换算

| 语言 | 1 token ≈ |
| --- | --- |
| 英文 | 0.75 个单词 |
| 中文 | 1–2 个汉字 |

> [!tip] 想要精确数字
> 用官方 tokenizer 工具数一遍，别靠估算。中文混排、代码、emoji 的切分结果经常和直觉差很多。

### 常见切分算法

| 算法 | 思路 |
| --- | --- |
| BPE | 从字符开始，反复合并最高频相邻对 |
| WordPiece | 类似 BPE，BERT 系在用 |
| SentencePiece | 语言无关，中文友好，能直接处理空格缺失 |

## 常见误解

> [!warning] Token 不是词，也不对齐语义
> - "unbelievable" 可能被切成 `un / believ / able` 三片——模型看到的和你的语感不同
> - 数字切法很怪（"1234" 可能是一整个 token，"12345" 被拆开），这是模型不擅长算术的原因之一
> - token 数 ≠ 字符数，复制粘贴长文前先数一遍，别撞窗口上限
