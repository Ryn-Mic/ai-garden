# 上下文：AI 这一轮的工作材料

> [!info] 阅读定位
> **独立知识点 · 入门**。不用编程。用于解释第一次文字练习之后的一个问题：AI 依据什么回答。

## 一句话理解

**上下文是应用在这一次调用中提供给模型的工作信息。** 可以把它类比成当前桌面上的资料，而不是整个资料柜。

你给的目标、材料、相关历史、工作说明，以及工具实际返回的结果，都可能成为其中的一部分。具体放入哪些内容，由应用的功能与处理方式决定。

## 用会议清单举例

| 信息 | 在这次任务中的作用 |
| --- | --- |
| “把会议记录整理成行动清单” | 当前目标 |
| “小陈整理问题，没有约定截止日期” | 当前材料与事实依据 |
| “没写的日期标待确认” | 工作要求 |
| “预算为 3000 元”的新补充 | 新的材料；不能倒推原文早就包含它 |

模型训练时学过的知识，不等于这一次读到了你的私人文件。补充一行事实，也不等于已经重新训练模型或永久保存了它。

## 为什么说过一次，后面还可能遗漏

可用信息有长度限制。应用可能保留部分历史、做摘要或按需检索；不保证每轮都带着所有原始细节。

长对话里，重新提供**当前目标、关键要求、必要材料和输出样例**，比反复说“永远记住”更容易检查。

## 怎样知道材料有没有进入任务

先核对你是否真正提供了正文，再结合附件或读取记录与原文依据。AI 的自我声明不能独立证明应用送入了完整材料。

权限、读取、进入模型输入的区别，继续看 [[concepts/AI能看到什么|AI 能看到什么]]；更深入的技术解释是 [[concepts/上下文工程|上下文工程]]，普通用户不必先读它。

本文是概念与检查框架，不表示已经核对每款应用完整的内部输入。
