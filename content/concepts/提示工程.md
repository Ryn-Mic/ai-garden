# 提示工程

> [!abstract] 一句话定义
> 不改模型权重，只通过设计输入文本来引导 [[大语言模型]] 输出的技术。**投入产出比最高**的能力杠杆。

## 为什么重要

同一个模型，提示写法不同，效果可以差出一个代际。在考虑 [[微调]] 之前，先把提示榨干。

## 核心原理

模型只做「续写」。提示工程的本质是**把任务构造成一个模型自然会续写对的上下文**。

### 基本构件

| 构件 | 作用 |
| --- | --- |
| 角色设定 | 收窄输出分布（"你是资深 SRE"） |
| 任务描述 | 明确动词与交付物 |
| 上下文 | 喂入相关资料 —— 见 [[RAG]] |
| 示例（Few-shot） | 用样本定义格式与边界 |
| 输出格式约束 | 要求 JSON / 表格，便于下游解析 |
| 思维链（CoT） | "先一步步分析" —— 提升推理类任务 |

### 常用模式

- **Few-shot**：给 2–5 个输入→输出对，比纯描述稳定得多
- **CoT / Zero-shot CoT**：「让我们一步步思考」
- **ReAct**：思考 → 行动 → 观察 的循环，是 [[Agent]] 的基石
- **角色 + 边界**：明确"不知道就说不知道"，抑制幻觉
- **Self-Consistency**：采样多次取多数答案

### 迭代方法

```text
写初版 → 构造 10–20 条测试用例 → 跑 → 看失败样本 → 改一处 → 再跑
```

> [!warning] 常见坑
> - 一次改多处，无法归因
> - 没有测试集，靠感觉调
> - 把该由检索解决的问题（缺知识）用提示硬凑 → 应该上 [[RAG]]
> - 把该由校验解决的问题（格式/数值）交给模型自觉
