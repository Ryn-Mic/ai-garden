# MCP

> [!info] 阅读定位
> **工具箱 · 入门**。不要求编程。先判断你是否需要接入工具；协议、服务端代码放在 [[research/analysis/MCP的接入与调用机制|MCP的接入与调用机制]]。

## 从一个日常问题开始

你让 AI 总结某个网页。它能写摘要，却可能没有打开网页的能力，只能根据链接或标题猜内容。

一种解决办法是让你正在用的 AI 应用接入一个网页读取工具。**MCP（模型上下文协议）就是应用与这类外部工具通信的一种标准方式**。

它像统一插口，但不是某一个插件，也不是“装上以后就什么都能做”。

## 你实际接入的是什么

| 名称 | 用普通话理解 | 例子 |
| --- | --- | --- |
| AI 应用 | 你正在操作的软件 | 支持 MCP 的桌面客户端 |
| MCP Server（服务端） | 提供外部能力的程序或服务 | 网页读取、文件查询、业务系统接口 |
| 工具 | 服务端开放的具体动作 | 获取某个 URL 的正文 |
| 授权 | 应用或服务允许访问的范围 | 只读某个文件夹，不允许删除 |

模型提出要用哪个工具，**实际执行由应用和工具服务负责**。模型一般得到的是工具说明和返回结果，不是自动获得整个电脑或数据库。

## 什么时候需要它

先检查应用是否已经自带能力。已有搜索、附件分析、网页浏览能解决问题时，不必再接一套 MCP。

| 需求 | 先尝试 | 什么时候再考虑 MCP |
| --- | --- | --- |
| 总结一份文件 | 上传文件或使用应用的文件功能 | 需要在明确范围内持续查询外部文件 |
| 查询公开信息 | 应用已有的搜索功能 | 缺少合适的数据或读取入口 |
| 读取一条网页链接 | 应用已有的网页读取功能 | 原有工具不能读取，且有合适的 MCP 服务 |
| 连接业务系统 | 官方集成或连接器 | 集成不足，需要定制接口和授权 |

用途记录：[[toolbox/mcp/网页读取MCP|网页读取MCP]]、[[toolbox/mcp/文件系统MCP|文件系统MCP]]。需要接入时，再看 [[tutorials/mcp/MCP从接入到验收|MCP从接入到验收]]（进阶使用，需要运行环境）。注意：**网页读取、搜索、浏览器操作是三种不同能力**，不能把名字相近的服务当作等价替代。

## 接入之前准备什么

1. **确定应用支持**：查该产品、该版本的 MCP 文档；没有入口就不要盲目套用别的软件配置。
2. **确认服务来源**：从官方说明获取地址或安装方法，不执行来历不明的命令。
3. **确认依赖与费用**：本地服务可能需要额外运行环境；远程服务可能需要账户或付费。
4. **划定权限**：能读什么、能写什么、是否会把资料发到远程服务。

有的产品提供图形化连接，有的需要填写启动命令或配置文件。**这是具体应用的差异，不存在一份适用于所有 Agent 的安装路径。**

如果步骤要求终端、Python 或密钥配置，而你不熟悉这些，找技术协作比照抄不明命令更安全。

## 连上了怎样判断成功

「连接正常」只说明应用可能能与服务通信，还没有证明本次任务调用了它。

拿一份公开测试资料，明确要求使用指定工具，检查：

- 应用有没有显示对应工具和调用记录。
- 工具是否返回了预期的资料，而不是错误或空内容。
- 回答中的事实能否在返回资料中找到。

AI 自称「已经连接」「已经查询」不是独立证据。找不到调用记录时，应把结论标为未确认。

## 安全边界

**只读也有风险**：读取公司文件可能把内容送到模型提供方或远程服务；网页中的恶意文字也可能试图诱导 Agent 改变任务。

先用公开资料、最小授权范围试用。发送消息、写业务数据、删除、支付等动作要有可验证的审批或权限控制。不要把 API 密钥写进聊天、截图或公开笔记。

## Skill 与 MCP 怎么配合

[[concepts/Skill|Skill]] 可以规定「整理报告前先读取来源、不能编造日期」，MCP 工具可以负责读取来源。**有流程但没有工具，读不到；有工具但没有验收，仍可能做错。**

自己做 Skill 可从纯文字开始；自己开发 MCP 通常需要编程、授权与部署经验，属于 [[research/index|进阶研究]]。
