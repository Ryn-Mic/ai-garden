# 学习路线

> [!abstract] 说明
> 从"会用"到"能自己搭"的四阶路径。每阶给一个**可验证的产出**，做出来再进下一阶——比刷完课程有效得多。

## 阶段 1：建立直觉（1–2 周）

**学**：[[大语言模型]] 是什么、能做什么、不能做什么；[[Transformer]] 的注意力机制。

**读**：[[Attention-Is-All-You-Need]]（不用推公式，看懂注意力在算什么就行）。

**产出**：用自己的话写下 [[大语言模型]] 的三条能力边界，并各举一个例子。

## 阶段 2：学会用好（2–4 周）

**学**：[[提示工程]]（Few-shot、CoT、结构化输出）、[[上下文工程]]。

**产出**：为一个真实重复任务写一套提示模板，并用 10 条测试用例验证稳定性。

> [!tip] 这一步的收益被严重低估
> 90% 的"模型不行"，在这个阶段就能解决。先别急着上 [[RAG]] 或 [[微调]]。

## 阶段 3：接上数据（1–2 个月）

**学**：[[Embedding]]、[[向量数据库]]、[[RAG]] 全链路；切分策略、混合检索、重排。

**练**：[[构建RAG应用]]。框架选 [[LlamaIndex]] 或 [[Dify]]。

**产出**：一个能回答自己文档的问答系统，且能给出处、能说"不知道"。

**选型**：什么时候该转向 [[微调]]，看 [[RAG与微调]]。

## 阶段 4：让它动手（持续）

**学**：[[Agent]] 的 ReAct 循环、工具设计、[[MCP]]、多 Agent 的取舍。

**练**：用 [[LangChain]] / [[LlamaIndex]] 写一个能调真实工具的 Agent；对比见 [[Agent框架对比]]。

**产出**：一个每天真的在用的自动化流程。判断标准很简单——**你自己愿不愿意每天用它**。

## 贯穿始终的习惯

| 习惯 | 为什么 |
| --- | --- |
| 每学一个概念就写一篇笔记并链进图谱 | 不链接的知识等于没记 |
| 记录失败样本 | 失败样本是最贵的资产 |
| 动手前先想评测怎么做 | 没有评测就没有迭代 |
| 优先用最简单的方案 | 提示 > [[RAG]] > [[微调]]，按成本递增 |
