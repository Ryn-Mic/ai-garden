# 多端同步与发布流程

> [!info] 目标
> 搞清「在哪写、写到哪、怎么上线」这三件事，多台设备之间不打架。

## 三条规则

1. **只在 Gitee 内容仓库写** —— 它是唯一真相来源
2. **站点仓库的 `content/` 是副本** —— 会被同步覆盖，别在那儿改
3. **推送即发布** —— Gitee 推完，最长 1 小时站点自动重建

## 新设备接入

```bash
git clone https://gitee.com/MeverikC/ai-garden-contents.git ai-garden-vault
```

Obsidian → **Open folder as vault** → 选克隆下来的目录（**仓库根目录就是 Vault 根**）。

`content/.obsidian/` 那套配置已经在仓库里了，打开即用——双链格式、附件目录、模板目录、图谱配色都不用重设。

## 日常循环

```bash
git pull
# …在 Obsidian 里写…
git add -A
git commit -m "note: 新增 xxx"
git push
```

> [!tip] 免敲命令
> 装 Obsidian 社区插件 **Git**：启动自动 pull，每 N 分钟自动 commit & push。手机和平板上的 Obsidian 也支持。

## 冲突怎么避免

| 场景 | 做法 |
| --- | --- |
| 两台设备改**不同**笔记 | 安全，Git 自动合并 |
| 两台设备改**同一篇** | 会冲突。**动笔前先 pull** |
| 当前打开的标签页 | `.obsidian/workspace.json` 已 gitignore，不会互冲 |
| 图片附件 | 都在 `assets/`，同名不同图会互相覆盖，文件名带上日期 |

## 发布链路

```text
Obsidian（任意设备）
   ↓  git push
Gitee: ai-garden-contents        ← 唯一真相来源
   ↓  GitHub Actions：每小时 cron / 手动触发
GitHub: Ryn-Mic/ai-garden 的 content/
   ↓  npx quartz build
GitHub Pages  →  https://ryn-mic.github.io/ai-garden/
```

## 立刻发布（不等定时）

```bash
gh workflow run deploy.yaml -R Ryn-Mic/ai-garden
```

或在 GitHub 仓库页面 → **Actions** → `Build & Deploy AI Garden` → **Run workflow**。

## 在站点仓库所在机器上写作

如果这台机器同时有站点仓库，改完 `content/` 后用脚本推回上游：

```bash
./scripts/push-vault.sh        # 同步并推送到 Gitee
./scripts/push-vault.sh -n     # 干跑，只看会改什么
```

## 常见坑

> [!warning] 踩坑记录
> - **改了 GitHub 的 `content/` 结果被覆盖**：这是**单向同步**的设计，不是 bug。上游是 Gitee。
> - **推了 Gitee 但站点没更新**：最长等 1 小时；急着看就手动 `gh workflow run`。
> - **CI 报「拉取 Gitee 内容失败」**：`GITEE_TOKEN` secret 缺失或过期。不会阻断构建，但这次内容不会更新。
> - **`git status` 里中文文件名显示成 `\351\205\215`**：Git 默认 `core.quotepath=true` 的八进制转义。不影响功能，想看清楚执行 `git config --global core.quotepath false`。
